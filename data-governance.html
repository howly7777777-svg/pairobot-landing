Data Governance

This page explains PaiRobot Meeting AI data handling model for enterprise and high-trust teams.

1) Default Retention Principle

PaiRobot Meeting AI ships with No Retention as default behavior. Meeting output is not automatically persisted to vendor-managed database by default.

2) Retention Modes

Mode Who controls storage Typical use case
No Retention (Default) User session only High-sensitivity meetings, legal-first teams
Local Device Storage User device Personal workflow and local-only record keeping
Customer-Managed Export Customer-selected destination Enterprise policy requiring customer-owned storage

3) Meeting Output Structure

Standardized output is generated for operations and review:

  • Summary
  • Decision log
  • Action items (task, owner suggestion, due date, confidence)
  • Follow-up email draft
  • Review flags for low-confidence extraction

4) User Controls

  • Select retention mode before exporting meeting result
  • Export history stored on local device only
  • Delete record only, or delete record and exported file
  • Copy output as text or JSON for downstream workflows

5) Governance Positioning

Governance Concern PaiRobot Position
Vendor data custody Not default. User decides retention destination.
Storage location control Supported via customer-managed export path.
Sensitive meeting content No-retention mode available by default.
Auditability of local exports Local export history index is available in app.
